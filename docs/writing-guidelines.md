# Writing Guidelines

## Objective

A writeup should explain the reasoning behind a solution and allow
another reader to understand and reproduce it within the same
authorized challenge environment.

## Recommended Method

For each significant step, document:

1. Observation
2. Hypothesis
3. Action or command
4. Result
5. Technical interpretation

## Quality Rules

- Explain why a command is used.
- Include relevant output, not excessive terminal noise.
- Separate confirmed findings from assumptions.
- Document failed approaches when they teach something useful.
- Keep scripts minimal and readable.
- Use code fences with the correct language.
- Avoid unsupported claims about impact.
- Include remediation when discussing a vulnerability.

## Reproducibility

Record relevant environment details, dependencies, and assumptions.
Do not promise reproducibility if the target environment is no longer
available or the result depends on undocumented conditions.

## Style

Use concise technical English, clear headings, and consistent terms.
